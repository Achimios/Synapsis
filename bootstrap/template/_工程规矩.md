# 项目详细规则（约定 + 指引）

> `AGENTS.md` 只放基石，要短；**怎么做**的细则都写在这里。改了规矩就改这份，不要散落在对话里。
> 通用部分来自 Synapsis 项目构建引导（`bootstrap/template/_工程规矩.md`）；本项目特有的写在最后一节。

## 1. `_过期的/`：过期内容移走，不删
- **就近放**：每个目录需要时自己建一个 `_过期的/`，不要集中到根目录。
- **两种过期方式**
  1. **整个文件过期** → 把文件移进同级的 `_过期的/`。
  2. **文件里的一段过期** → 把那段**剪切**出来，追加到同级 `_过期的/<原文件名>`（同名文件，没有就新建），段前加标题 `## YYYY-MM-DD · 从 <原文件> 剪出`。原文件只留结论，或者一行指针。
- **什么时候**：每一轮工作收尾时顺手做（和更新 `__where_continue.md` 同一时间），别攒着。
- **不删**：👤 的规矩。`_过期的/` 里的东西 AI 不再读，人想翻旧账时去翻。

## 2. 进度文件写什么、不写什么
- `_开发进度.md` **只留现在有用的**：各模块当前状态（一行）、功能级里程碑、👤 决定、⚠️ 还没验到的。
- **修好的小 bug、技术过程（怎么查出来的、试过什么）** → 修完那一轮就剪到 `_过期的/_开发进度.md`。
  - 其中**机理值得记住的**（下次还会踩），提炼成一条写进 `_LEARNINGS.md`（坑 + 为什么 + 怎么避），过程本身仍然过期。
- `__where_continue.md` 一屏：只写「现在在做什么 / 下一步 / 等用户决定什么」，旧的剪去过期。
- 判断标准：**下一个接手的 AI 读了这行，会不会做出不同的事？** 不会，就该过期。

## 3. 改了东西要同步的清单
| 改了什么 | 同步哪里 |
|---|---|
| 加了 / 改了功能 | 代码里的 `>v<` 锚点 + `_开发索引.md` + `_开发进度.md` 一行 |
| 来自 👤 的抱怨 / 卡点 | `-给人类的解释/-摩擦日志.md`（原话 + 怎么处理的） |
| 踩了值得记的坑 | `_LEARNINGS.md`；很常见的提到 `AGENTS.md` 常见坑 |
| 做完了待办 | `_TODO.md` 打勾（或剪去过期） |
| 定了一个设计决定 | `_设计/` 对应文件，标 👤 / 日期 |
| 一轮收尾 | `__where_continue.md`、过期清理、git 提交 |

- 目录与启动约定（`src/`、`启动脚本/`、`安装依赖.bat`、`添加到开始菜单.bat`、国内源、图标、托盘、凭证首次运行）见 Synapsis `bootstrap/_项目构建引导.md` 的 **§5b**。不是小工具的项目跳过这一节。
