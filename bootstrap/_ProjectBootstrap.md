# Synapsis 项目构建引导（给 LLM：新建/接手一个项目时照这个做）

> 来源：用户 Leo 的 ReadScreen / TTS / SimuWeb / Synapsis 等项目沉淀下来的规矩（2026-10-07 汇总）。
> **怎么用**：`node <Synapsis>/bootstrap/bootstrap.js <项目目录> --name 名字 --desc "一句话"` 生成骨架（不覆盖已有文件），然后按 §6 跟用户补内容。
> 模板在 `bootstrap/template/`；改规矩就改这份 + 模板，所有新项目跟着变。

---

## 1. 人（最重要）
- 用户 Leo：游戏开发者 / 玩法设计师。**回复用中文**（偶尔夹德语）。**很累时不要让他做琐碎决定**——有惯例就按惯例，做完说一声。
- ⭐**别完美主义**：👤「不要纠结于完美主义和细节，整体才重要，能快速体验才重要，生活本身才重要。不要让局部打断迸发的灵感。」
- 用户累时文字会丢在对话里 → **待办、思考、设计、摩擦点由 AI 代记进项目文档**，别让他自己整理。

## 2. 判据（思维风格）
- **结构对、量级对、留校准空间**；不假装比实际精确；宁可简单快，不要通用慢。
- ⚠️**报错的伦理**：把**没做到、没验到的那一半也写出来**。嘴硬只能用在「我来修」，不能用在「没事」。报告里分开写【实测】【设计】【估计】【未验】。
- ⚠️**数字对了 ≠ 机理对了**。⭐**找一个「必须相等」的量**当免费交叉校验（往返无损、两条通路结果逐字相等、步长之和 = 位移）。
- ⚠️**别人（含自己）的方案先验前提**，别因为成体系就采信。⭐**两个 AI 说同样的话不是交叉验证**（可能同源），值钱的是**分歧点**。
- ⭐**能在 Node / 命令行里验证的，别靠浏览器或人眼**；UI 也尽量自动化（playwright-core + 本机 Edge 无头，不用下载浏览器）。

## 3. 权威度（决定什么能直接做）
| 类别 | AI 可以直接做 | 必须等用户 |
|---|---|---|
| 代码 / 自检 / 文档补全 / 修 bug | ✅ **全绿就提交，不用问** | —— |
| 重构、改目录结构 | ✅ 先说要做什么，然后做 | —— |
| 判据、原则、`AGENTS.md` 的基石部分 | ⚠️ 可以起草 | ⭐用户逐条过 |
| 👤 标记过的决定 | ❌ 只能引用 | ⭐推翻要显式说并给证据 |
| 删文件 / 改用户笔记原件 | ❌ → 移进 `_过期的/` | ⭐永远等 |
| 别人的仓库 | ❌ | ⭐永远等 |
- ⚠️「问一句」不等于谨慎：为一处文档追加反复问，是把决策推给一个已经很累的人。
- git：👤「大更新都得先 git」。提交信息 `feat:/fix:/docs:/chore:` + 中文摘要。

## 4. 文档分层（`_` 前缀 = AI 读；`-` 前缀 = 人读；进代码的文件名用英文）
| 文件 | 干什么 |
|---|---|
| `AGENTS.md` | **基石，唯一本体**，要短。只放：是什么 / 判据 / 当前专注 / 权威度 / 分层指路。⚠️**不写具体路径、命令、数值、结论**（会过期、会被当真） |
| `CLAUDE.md` | 只一行 `@AGENTS.md`（每次对话全文加载，所以 AGENTS.md 必须短） |
| **分布式 AGENTS** | 代码子目录有需要的地方各放一份 `AGENTS.md` + `CLAUDE.md`(@AGENTS.md)：该目录职责、约定、坑。短；详细的进 `_LEARNINGS.md` |
| `_where_continue.md` | ⭐**接手第一眼**：现在在做什么 / 下一步。**一屏**，每天收工更新，旧内容移 `_过期的/` |
| `_DevProgress.md` + `_Progress/<模块>.md` | 索引 + 按模块详细进度。模块文件固定结构：**状态一行 / 👤决定 / 已实现且验过 / ⚠️没验到 / 下一步** |
| `_Plan.md` | 路线图（打算做什么、为什么），和进度分开 |
| `_TODO.md` | 未来要做的；想法池单独一节（💡） |
| `_DevIndex.md` | `>v<` 锚点表：开头格式说明 + grep 示例 → **大标题一览**（标记 / 涉及范围 / 说明）→ 每个大标题一节列小标题（做什么、在哪、坑与为什么）。范本：模板里的 `_DevIndex.md` |
| `_LEARNINGS.md` | 坑点，带翻车现场；**很常见的坑直接写进 AGENTS.md** |
| `_Design/` | 设计长文（哲学、规格、决定） |
| `_Blackboard.md` | （多 AI 协作时）临时话，看完清，结论不沉淀在这 |
| `-项目结构.md`、`-给人类的解释/` | 人读的 |
| `-给人类的解释/-摩擦日志.md` | 用户卡住的地方（AI 代记），是需求来源 |
| `_过期的/` | 过期内容**移进来而不是删**；分布式（就近放） |
- 旧项目用中文名（`_开发进度.md` `_开发索引表.md` `_进度/` `_规划.md` `_交流黑板.md`），新项目用英文名；工具两种都认。

## 5. 代码约定
- 锚点注释：`>v<[emoji]大标题-小标题-一句话注释`，例 `>v<🎯OCR-ROI识别-固定区域只跑识别不跑检测`。找功能：先在 `_DevIndex.md` 找大标题，再全局 grep。**加功能必须同步加锚点和索引。**
- ⚠️ 在 Markdown 里写标记一律包反引号 `` `>v<…` ``：行首的 `>` 会被当成引用块。
- 改了任何行为，同步：`_DevProgress` / `_DevIndex` / `_LEARNINGS`（用户会检查文档是否同步）。
- 自检脚本放 `tests/`，一条命令跑完，输出 `N 过 / M 挂`；前台命令必须带 timeout，后台任务等通知、别 sleep 死等。
- **启动**：常驻服务用根目录 `XXX_start.vbs`（无窗口，已在跑就不重复起）+ `XXX_stop.bat`；能做就加「没有客户端时自动退出」。**.bat / .vbs / requirements.txt 保持纯 ASCII**（GBK 会崩）。
- 中文在 Windows：调 CLI 传中文走 Bash（PowerShell 5.1 会变 `??`）；Git Bash 里含反斜杠路径别用 sed 改（`\U` 等会被吃）。
- 凭证 `config/creds.*` **绝不提交**；大文件（模型、缓存）gitignore。
- 新增第三方依赖要克制；可选功能缺依赖只记日志、不影响主功能。

## 6. 新建项目的流程（AI 照做）
1. 跑 `bootstrap.js` 生成骨架（已有文件跳过，不覆盖）；没有 git 就 `git init`。
2. 跟用户**用一两句话**确认：这是什么、精度定位、当前专注 → 写进 `AGENTS.md` 的对应格子。**别一次问一堆**，问不清的先写「待定」。
3. 写 `_where_continue.md` 第一版；第一个提交 `chore: 项目骨架（Synapsis bootstrap）`。
4. 之后边做边长：子目录出现明确职责时再加分布式 AGENTS.md，不要预先建空壳。
5. 被 Synapsis 规划时：项目根建 `__synapsis/`（图数据，进 git）与 `.synapsis/`（本机状态，gitignore）。
