# Synapsis 项目构建引导（给 LLM：新建/接手一个项目时照这个做）

> 来源：用户 Leo 的 ReadScreen / TTS / SimuWeb / Synapsis 等项目沉淀下来的规矩（2026-10-07 汇总）。
> **怎么用**：`node <Synapsis>/bootstrap/bootstrap.js <项目目录> --name 名字 --desc "一句话"` 生成骨架（不覆盖已有文件），然后按 §6 跟用户补内容。
> 模板在 `bootstrap/template/`；改规矩就改这份 + 模板，所有新项目跟着变。

---

## 1. 人（最重要）
- 用户 Leo：游戏开发者 / 玩法设计师。**回复用中文**（偶尔夹德语）。**很累时不要让他做琐碎决定**——有惯例就按惯例，做完说一声。
- ⭐**别完美主义**：👤「不要纠结于完美主义和细节，整体才重要，能快速体验才重要，生活本身才重要。不要让局部打断迸发的灵感。」
- 用户累时文字会丢在对话里 → **待办、思考、设计、摩擦点由 AI 代记进项目文档**，别让他自己整理。

## 2. 判据（思维风格）
- **结构对、量级对、留校准空间**；不假装比实际精确；宁可简单快，不要通用慢。
- ⚠️**报错的伦理**：把**没做到、没验到的那一半也写出来**。嘴硬只能用在「我来修」，不能用在「没事」。报告里分开写【实测】【设计】【估计】【未验】。
- ⚠️**数字对了 ≠ 机理对了**。⭐**找一个「必须相等」的量**当免费交叉校验（往返无损、两条通路结果逐字相等、步长之和 = 位移）。
- ⚠️**别人（含自己）的方案先验前提**，别因为成体系就采信。⭐**两个 AI 说同样的话不是交叉验证**（可能同源），值钱的是**分歧点**。
- ⭐**能在 Node / 命令行里验证的，别靠浏览器或人眼**；UI 也尽量自动化（playwright-core + 本机 Edge 无头，不用下载浏览器）。

## 3. 权威度（决定什么能直接做）
| 类别 | AI 可以直接做 | 必须等用户 |
|---|---|---|
| 代码 / 自检 / 文档补全 / 修 bug | ✅ **全绿就提交，不用问** | —— |
| 重构、改目录结构 | ✅ 先说要做什么，然后做 | —— |
| 判据、原则、`AGENTS.md` 的基石部分 | ⚠️ 可以起草 | ⭐用户逐条过 |
| 👤 标记过的决定 | ❌ 只能引用 | ⭐推翻要显式说并给证据 |
| 删文件 / 改用户笔记原件 | ❌ → 移进 `_过期的/` | ⭐永远等 |
| 别人的仓库 | ❌ | ⭐永远等 |
- ⚠️「问一句」不等于谨慎：为一处文档追加反复问，是把决策推给一个已经很累的人。
- git：👤「大更新都得先 git」。提交信息 `feat:/fix:/docs:/chore:` + 中文摘要。

## 4. 文档分层（`_` 前缀 = AI 读；`-` 前缀 = 人读；进代码的文件名用英文）
| 文件 | 干什么 |
|---|---|
| `AGENTS.md` | **基石，唯一本体**，要短。只放：是什么 / 判据 / 当前专注 / 权威度 / 分层指路。⚠️**不写具体路径、命令、数值、结论**（会过期、会被当真） |
| `CLAUDE.md` | 只一行 `@AGENTS.md`（每次对话全文加载，所以 AGENTS.md 必须短） |
| **分布式 AGENTS** | 代码子目录有需要的地方各放一份 `AGENTS.md` + `CLAUDE.md`(@AGENTS.md)：该目录职责、约定、坑。短；详细的进 `_LEARNINGS.md` |
| `__where_continue.md` | ⭐**接手第一眼**：现在在做什么 / 下一步。**一屏**，每天收工更新，旧内容移 `_过期的/` |
| `_开发进度.md` + `_进度/<模块>.md` | 索引 + 按模块详细进度。模块文件固定结构：**状态一行 / 👤决定 / 已实现且验过 / ⚠️没验到 / 下一步** |
| `_PLAN.md` | 路线图（打算做什么、为什么），和进度分开 |
| `_TODO.md` | 未来要做的；想法池单独一节（💡） |
| `_开发索引.md` | `>v<` 锚点表：开头格式说明 + grep 示例 → **大标题一览**（标记 / 涉及范围 / 说明）→ 每个大标题一节列小标题（做什么、在哪、坑与为什么）。范本：模板里的 `_开发索引.md` |
| `_LEARNINGS.md` | 坑点，带翻车现场；**很常见的坑直接写进 AGENTS.md** |
| `_设计/` | 设计长文（哲学、规格、决定） |
| `_Blackboard.md` | （多 AI 协作时）临时话，看完清，结论不沉淀在这 |
| `-项目结构.md`、`-给人类的解释/` | 人读的 |
| `__<名字>_详细规则.md` / `__<名字>_调用方法(仅演示).md` | 对外接口规格 / 给别的项目生成调用方法的样板。**`__` 前缀 = 最先要读的规格**；`AGENTS.md` 里放一张“要做什么 → 读哪个文件”的读取表 |
| `README.md` | 给 GitHub 读者（人）看；第一节是“把项目路径丢给你的 AI，让它带你装”，其后是安装 / 配凭证 / 日常使用 |
| `-如何开通XXX.md` | 给小白的外部服务开通教程（带截图，不放代码自检） |
| `-给人类的解释/-摩擦日志.md` | 用户卡住的地方（AI 代记），是需求来源 |
| `_工程规矩.md` | ⭐**项目详细规则**（约定 + 指引）：过期怎么做、进度写什么不写什么、改了要同步哪。AGENTS.md 只指过来。通用部分在模板里，项目特有的写最后一节 |
| `_过期的/` | 过期内容**移进来而不是删**；分布式（就近放）。整个文件移进来，或把一段**剪切**到同级 `_过期的/<原文件名>`；修好的小 bug 和技术过程当轮就过期 |
- 旧项目用中文名（`_开发进度.md` `_开发索引表.md` `_进度/` `_规划.md` `_交流黑板.md`），新项目用英文名；工具两种都认。

## 5. 代码约定
- 锚点注释：`>v<[emoji]大标题-小标题-一句话注释`，例 `>v<🎯OCR-ROI识别-固定区域只跑识别不跑检测`。找功能：先在 `_开发索引.md` 找大标题，再全局 grep。**加功能必须同步加锚点和索引。**
- ⚠️ 在 Markdown 里写标记一律包反引号 `` `>v<…` ``：行首的 `>` 会被当成引用块。
- 改了任何行为，同步：`_开发进度` / `_开发索引` / `_LEARNINGS`（用户会检查文档是否同步）。
- 自检脚本放 `tests/`，一条命令跑完，输出 `N 过 / M 挂`；前台命令必须带 timeout，后台任务等通知、别 sleep 死等。
- **启动**：常驻服务要无窗口启动（`.vbs`），已在跑就不重复起；能做就加「没有客户端时自动退出」。**.bat / .vbs / requirements.txt 保持纯 ASCII**（GBK 会崩）。⭐可交付的小工具（有安装、托盘、GUI）的目录与脚本约定见 **§5b**（2026-10-14 起：脚本进 `启动脚本/`，代码进 `src/`）。
- 中文在 Windows：调 CLI 传中文走 Bash（PowerShell 5.1 会变 `??`）；Git Bash 里含反斜杠路径别用 sed 改（`\U` 等会被吃）。
- 凭证（`config/cred.json` 等）**绝不提交**，只提交 `cred.example.json`；大文件（模型、缓存）gitignore。**对话里别打印凭证字段**（连前半段也别，看文件格式时只看字段名）。
- 新增第三方依赖要克制；可选功能缺依赖只记日志、不影响主功能。

## 5b. 做成可交付的小工具（常驻服务 / GUI / 托盘）时的目录与启动约定
> 来源：2026-10-14 整理 TTS / ReadScreen / ASR 三个项目时定下的。**不是小工具的项目（纯文档、游戏、网页）不用管这一节。**
- **目录**：代码进 `src/`；根目录只留 `AGENTS.md` / `README.md` / 配置 / 文档 / 启动与安装脚本。⚠️如果别的项目会按路径调用某个入口（如 `tts_v1.py`），**根目录留一个薄壳转发**，不要搬走或改名（薄壳里 `sys.modules[__name__] = 真模块`，被 import 和被当脚本运行都不坏）。
- **启动脚本放 `启动脚本/`**（`.vbs` 无窗口启动；`.bat` 第一行 `cd /d "%~dp0.."`；`.vbs` 用“上一级的上一级”当根目录）。**`安装依赖.bat`、`停止XXX.bat`、`添加到开始菜单.bat` 留在根目录。** `.bat` / `.vbs` / `requirements.txt` **内容纯 ASCII**（文件名可以中文）；`.bat` 用 CRLF；含中文的 `.ps1` 存 UTF-8 **带 BOM**。
- **`安装依赖.bat` 标准流程**（便携版没有安装程序，用它代替）：检查 Python ≥ 3.10 → 没有 `.venv` 才建 → `.venv` 里缺 pip 就 `ensurepip` → `pip install -r requirements.txt` 先用**清华源**，失败回退官方 → 验证关键 import → 下载模型（见下）→ 停掉旧的后台服务（下次调用自动拉起新环境）。可选的大模型文件问一句 Y/N，默认 N。
- **国内源优先**：pip 用清华；模型用 ModelScope 等国内源，并按官方给的 SHA256 校验；国外源只当回退（以后出英文版再切）。没有可靠国内镜像的可选资源（如 GitHub release 里的唤醒词模型），保持官方地址 + 可选。
- **`添加到开始菜单.bat`**：调一个 `.ps1` 创建 / 更新开始菜单快捷方式（指向 `启动脚本/` 里的入口 + `assets/icon.ico`）。**幂等**：按目标匹配已有的快捷方式就地更新，不重复新建。
- **图标**：`assets/icon.ico` + `icon.png`，窗口、托盘、快捷方式都用它。⚠️ `pythonw` 的窗口默认归在 Python 图标下（甚至没图标），要在创建窗口前设**独立的 AppUserModelID**（`SetCurrentProcessExplicitAppUserModelID`），再设窗口图标。
- **托盘菜单**：打开界面 / 日志 / 重启 / 停止。
  - 点“打开界面”：**窗口已经开着就只切前台**（按窗口标题精确匹配；最小化的先还原；用“临时挂接前台窗口输入线程”切前台，别用“按一下 Alt”——慢约一倍，还会把 Alt 键塞进目标窗口）。
  - “重启”：拉起一个**脱离本进程**的助手（`DETACHED_PROCESS|CREATE_NO_WINDOW`，**stdin/stdout/stderr 给 DEVNULL**——`pythonw` 下 `sys.stdout` 是 `None`，脚本里 `stdout.reconfigure` 会直接崩），由它关旧、等端口释放、拉新；写 `logs/restart.log`；等 ≥ 30 秒才算失败。
  - GUI 要能扛住服务重启：连不上时只记第一条错误，服务回来后自己清掉提示。
- **GUI 布局**：日志区随窗口高度伸缩，窗口最小高度 = 内容自然高度（屏幕放不下才出整页滚动条）。
- **凭证**：`config/cred.example.json` 入库（占位值乱写），真实 `cred.json` 不入库；**首次运行没有 `cred.json` 就从 example 复制**；示例里含中文的占位文字一律当“没填”（真密钥全是 ASCII）。
- **给新手的文档**（如 `-如何开通XXX.md`）：不放代码和命令自检，用软件里的按钮和状态行；截图放 `assets/` 下 ASCII 文件名，用相对路径 `![](assets/…)`，GitHub 能直接显示。
- **测试**：语音 / 云端这类便宜的服务，直接用真实后端测，不必造假后端。

## 6. 新建项目的流程（AI 照做）
1. 跑 `bootstrap.js` 生成骨架（已有文件跳过，不覆盖）；没有 git 就 `git init`。
2. 跟用户**用一两句话**确认：这是什么、精度定位、当前专注 → 写进 `AGENTS.md` 的对应格子。**别一次问一堆**，问不清的先写「待定」。
3. 写 `__where_continue.md` 第一版；第一个提交 `chore: 项目骨架（Synapsis bootstrap）`。
4. 之后边做边长：子目录出现明确职责时再加分布式 AGENTS.md，不要预先建空壳。
5. 要用 Synapsis 规划：双击 `<Synapsis>/Synapsis_desktop.vbs` 开客户端 → 启动台「打开文件夹」选项目（没挂上会自动挂上；或 `node <Synapsis>/core/cli.js init <目录>`）→ 生成 `__synapsis/`（图数据，进 git）、`.synapsis/`（本机状态，自带 gitignore）、根目录 `Synapsis.vbs` 启动器。
