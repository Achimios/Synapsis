# 导航：在自己脑海里导航（需要下功夫的一块）

> 2026-10-07。👤 = 用户原话。实现状态：✅ 已做（app） / 💡 想法，未做。

## 0. 定位（👤）
> 「Google 的诞生是允许你在世界 web 中导航，而 Synapsis 是帮助你在自我脑海中导航和记录。」

所以导航不是附属功能，是**主功能**之一。层级会非常多（游戏设计规划 ⊃ AI 行为 ⊃ 决策 ⊃ 状态机 …）。

## 1. 导航原语（按浏览器 / 地图 / IDE 的已有经验）
| 原语 | 类比 | 状态 |
|---|---|---|
| 钻进 / 退出（面包屑） | 文件夹 | ✅ 双击 / Alt+↑ / 面包屑 |
| 后退 / 前进 | 浏览器 | ✅ Alt+← / Alt+→ |
| **每个范围记住视图**（平移+缩放），回来时还原 | 地图 App | ✅（👤「返回上一级后得记住视图大小和位置」） |
| 传送门：跨层连线的端点，双击跳过去 | 超链接 | ✅ |
| 跳转：Ctrl+K 模糊搜索任意节点（名称 + 语义） | VS Code Ctrl+P / Google | 💡 |
| 语义缩放：缩小只看标题，放大才显示内部；缩到底自动「退一层」、放大到节点上自动「钻进」 | 地图的 LOD | 💡 |
| 沿边走：选中后方向键沿入/出边跳 | 图游走 | 💡 |
| 迷你地图标出「我在哪一层、哪一块」 | 游戏小地图 | 💡（RF 有平面小地图，没有层级感） |

## 2. 中键 = 旋转 = 基变换（👤 2026-10-07 灵感，**等更多灵感再定**）
现在中键和右键都是平移，浪费了一个轴。想法：**中键拖动 = 换视角**。

同一批节点其实同时有多套坐标：
| 投影（基） | 坐标从哪来 |
|---|---|
| 设计视图 | 人摆的 x,y（默认） |
| 层级视图 | 树布局 |
| 流向视图 | 按边分层（现在的自动布局） |
| **语义视图** | 节点文字的嵌入向量 → PCA/UMAP 到 2D（见 §3） |
| 标签视图 | 两个标签轴张成的平面（如 x=频率层，y=实现状态） |
| 时间视图 | 创建/修改时间、或开发进度 |

「旋转」= 在两套投影之间**连续插值**（节点平滑地从一套坐标滑到另一套）。这正是高维空间里的基变换 / 不同切片视角：
每个节点是高维向量（设计坐标 ⊕ 嵌入 ⊕ 标签 ⊕ 时间），屏幕是它的一个 2D 切片，中键拖 = 转动切片平面。
- 好处：保留**物体恒常性**（看着节点滑过去，就知道「它在另一种眼光下跑到哪」），这是切换视图时最容易丢的东西。
- 风险：插值中间态可能没有意义；先只做「两套投影之间的滑杆」验证值不值。

## 3. 向量空间 / 语素 / 标签：引导思维与结构感知（👤 问「是否有一个地方可以嵌入」）
放的地方：**节点的元数据 + 一个「观察层」**，不改节点本身。

1. **标签 = 正交于层级的轴**。层级只能表达「属于」；标签表达「横切」（如 #兜底 #外显 #实时 #待验证）。用途：过滤、着色、标签视图（§2）。成本低，v1 后最先做。
2. **嵌入向量（本地模型）**：每个节点的文字 → 向量（LM Studio 的 embeddings 接口可试，**未验证**）。三种用法：
   - **语义近邻**：「这两个节点意思很近，但没有连线」→ 提示可能漏了关系（结构感知）
   - **语义视图**：投影到 2D 看思维的「地形」，哪里扎堆、哪里空白（空白 = 还没想到的区域？）
   - **语义搜索**：Ctrl+K 不只按名字，按意思找
3. **结构度量（借 Google 的 PageRank 思路）**：按连线算中心度 → 「你以为的核心」vs「连线显示的核心」；孤岛、桥节点、只进不出的节点。这是用链接结构反过来照见思维。
4. 原则：这些都是**观察层，只提示不改图**；提示要标「推测」，由人决定接不接受（同虚影节点）。

## 3.5 嵌入实验 #1（2026-10-07，【实测】`core/tools/embed_probe.js`）
👤 问：「需不需要跑本地 8B 模型等方式来寻找语素向量关系？以后不止语素，代码、数学结构等都要。用本地 LLM/SLM 是因为懒得训练自己的模型。」

**数据**：研究工作区 15 个叶子、105 对；模型 nomic-embed-text-v1.5（LM Studio 已装）。
| 文本 | 有连线 | 没连线 | 效应量 |
|---|---|---|---|
| 名字 + math + 正文前 300 字 | 0.816 ± 0.033 | 0.789 ± 0.029 | 0.86 |
| 只有名字 | 0.883 ± 0.068 | 0.844 ± 0.069 | 0.56 |

**结论**：有信号（连过线的更像），但分辨力差——全部挤在 0.75–0.86；「最像但没连线」的候选多半被正文里的代码片段带偏（如 动作状态机 ↔ 敌方观察）。nomic 偏英文，中文短文本不行。n=15，结论粗。

**判断（推测，待下一轮实测）**：
- 找「向量关系」用**嵌入模型**，不用 8B 对话模型；嵌入模型本身就是预训练好的，不用自己训练。下一个候选：**多语种 + 代码**的嵌入模型（如 Qwen3-Embedding 0.6B、bge-m3），需要下载 GGUF；LM Studio 能否加载**没验证**。
- **8B 对话模型的位置**：不是算相似度，而是给候选关系**下判断和命名**（「A 是 B 的输入吗？是什么类型？」），以及给聚类起名字、生成基变换的轴名。用得少、用在刀刃上。
- **代码与数学结构先走精确结构**：import / 调用图 / AST、公式解析（不需要 ML，结果是真的）；嵌入只补「意思像」，LLM 只补「判断」。三层：**精确结构 → 嵌入相似 → LLM 判断**。
- 向量缓存放 `.synapsis/`（本机、可重算，按 内容 hash + 模型名 做 key），不进 git。
- 判据沿用本实验：**有连线 vs 没连线的效应量**，外加「候选里人认为有用的比例」。

## 3.6 嵌入实验 #2（2026-10-07，Qwen3-Embedding-0.6B Q8_0，ModelScope → `E:/2a_Code_Wares/LLMs/Qwen/`，LM Studio 自动识别）
| | nomic（LM Studio 自带，84 MB） | Qwen3-Embedding-0.6B（639 MB） |
|---|---|---|
| 相似度分布 | 0.75–0.86 | **0.38–0.72** |
| 有连线 vs 没连线 效应量（名字+说明） | 0.86 | 0.72 |
| 同组 vs 跨组 | 0.813 / 0.794 | **0.535 / 0.451** |
| 只用名字 效应量 | 0.56 | **0.74** |

⭐**机理（比数字重要）**：嵌入衡量的是「**同类**」，不是「**相连**」。Qwen3 的候选全是兄弟（敌方观察↔队友观察、LLM 兜底↔2B SLM），讲得通；但 AI 空间图的边大多连**不同类**（观测→决策），所以「有连线」的效应量不升反降。
→ **嵌入用于**：自动分组 / 语义搜索（Ctrl+K）/ 找重复 / 找兄弟 / 语义视图（基变换的一条轴）。**连线建议**：交给 8B 判断（「A 是 B 的输入吗？」）或代码精确结构。
→ 默认嵌入模型定 Qwen3-Embedding-0.6B（中文好、短文本稳、也懂代码；**代码效果没测**）。
