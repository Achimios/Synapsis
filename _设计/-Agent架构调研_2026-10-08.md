## 1. 先答核心问题：Claude Code 优秀是因为思维链吗？

**不是单一原因，更不主要是「思维链」。** 按证据强弱：

| 因素 | 证据 | 说明 |
|---|---|---|
| ① 模型与 harness 一起打磨 | 🟡⚠️ | 模型在这套工具/循环里被训练和评测，行为（何时读文件、何时停、怎么处理工具报错）已经和 harness 对齐。这是别家（只能换模型的 OpenCode/Hermes）最难复制的。 |
| ② 循环很普通，细节很多 | 🟡 | 核心就是「模型发工具调用 → harness 执行 → 结果回灌」。价值在外围：工具报错变成**结构化反馈**让模型自己重试；大输出**截断保关键**；读操作并发、写操作串行；每次调用过权限检查。 |
| ③ 上下文工程 | 🟡 | 系统提示**模块化并按「稳定在前、动态在后」排序**以吃 prompt cache（二手称可省到 90%）；自动压缩；三层记忆（见 §3）。 |
| ④ 扩展机制成熟 | 🟡 | CLAUDE.md、Skills、Hooks、MCP 分层。 |
| ⑤ 思维链/扩展思考 | ⚠️ | 有帮助（复杂任务靠它），但各家都有；不是区分点。 |
| ⑥ 项目规划 | 🟡 | 有 Plan 模式，但 OpenCode 也有 Plan/Build 分离；**不是**独有。泄露中被提到的 ULTRAPLAN（云端 Opus 规划最多 30 分钟）是**未发布**功能。 |

**论文视角（✅ 摘要）**：《Harness Engineering》对 11 个系统做了源码研究（Claude Code、Codex CLI、Gemini CLI、Mistral Vibe、OpenHands、Aider、Mini-SWE-Agent、Hermes、Pi、OpenCode、OpenClaw）。两条很有信息量的发现：
- **没有一个系统用通用 agent 框架**（LangChain 之类），全是手写异步循环；
- **没有一个用向量嵌入检索代码**，全是确定性检索（grep/glob/读文件）。
- Skills 采用率（9/11）已超过 MCP（8/11）；行为策略正从提示词文本迁移到配置；各家正在「趋同变模仿」。

## 2. 谁更优秀？

没有绝对排名，且**各家测的不是同一件事**：

| | 取向（一句话） | 模型绑定 | 弱点 |
|---|---|---|---|
| Claude Code | 想法→可审阅 diff 的摩擦最小；最成熟的 harness（CLAUDE.md/Skills/Hooks） | 仅 Anthropic | 闭源。（~~记忆偏薄~~ 已过时：现在有 auto memory，见 §7） |
| Codex CLI | 爆炸半径最小（沙箱）；MIT；原生子代理 | 仅 OpenAI | 输出质量波动；插件生态还在长 |
| OpenCode | 任意模型、不求许可；Plan/Build 分离；细粒度权限 | 无 | 依赖你选的模型 |
| Hermes | 个人常驻 agent：**学习循环**（做完难任务自动沉淀 skill）+ 用户建模 + 多渠道 | 无 | 年轻；学习循环可能学错模式；安全问题 |
| OpenClaw | 常驻网关 + 聊天渠道 + 文件记忆 + skills | 无 | 安全（有报道 923 个无认证网关暴露） |
| DeepSeek Harness | 可组合运行时（插件/profile） | 无 | 开发者预览；我抓到的页面是**半推广性质**，没有基准，别当证据 |

🟡 一项跨 harness 的安全评测里：Codex 综合最高（62.3），Claude Code 58.7，OpenClaw 55.4，OpenCode 48.4，Hermes 44.5；但在「子代理委派」一项 OpenCode 最高（64.0），Codex 只有 46.7。**结论：排名随任务变。** 另一项研究发现，Claude Code 是唯一在开源模型上仍能保持不错成绩的 harness——说明 harness 本身确实有独立价值，不全是模型。

## 3. 泄露的 Claude Code 里能学到什么（🟡 全部来自第三方分析）

> 法律提醒：代码归 Anthropic。**学思路，别抄代码。** 数字（行数、工具数）各家不一致，我只取机制。

- **三层记忆**：L1 `MEMORY.md` 索引（常驻，每行约 150 字，只当指针）→ L2 会话上下文 → L3 文件化的跨会话知识（按需加载）。⭐这和你 Synapsis 内置 AI 刚做的「只强制附一行一条的索引，全文自己回读」**几乎是同一个设计**——方向对。
- **autoDream（空闲时做梦）**：空闲时 fork 子代理合并多会话观察、**消除自相矛盾、把「暂定」升为「确认」**。即记忆有**置信度升级**和**去矛盾**，而不是只追加。
- **工具失败是数据**：错误变结构化反馈回灌，让模型自己改。
- **缓存感知的提示词布局**：稳定的在前，会变的在后；工具列表也排序以保缓存。
- **编译期开关**：44 个特性开关、死代码消除。
- **KAIROS（未发布）**：常驻后台模式，周期性 `<tick>`，自己决定行动还是休眠；追加式日志可审计；主动行动的阻塞预算 15 秒。⚠️ 对你的 NPC 很有启发：**「醒来→决定做不做」**本身就是决策空间的一个原语。
- **协作靠提示词而非复杂代码**：多代理协调主要由精心写的系统提示完成；子代理靠**工具白名单**限权。
- **反面教材**：发布时把 59.8MB source map 打进 npm 包。用 `files` 白名单而不是 `.npmignore`。

**Anthropic 自己的观点（🟡 二手）**：harness 里的每个机制都编码了「模型自己做不到什么」的假设，**模型变强后这些假设会过期**（例：Sonnet 4.5 需要的上下文重置，到 Opus 4.5 就不需要了）。→ 脚手架要能**随模型升级而删**。

## 4. OpenClaw 用什么方案？倾向代码吗？

🟡 结构：**Gateway（路由）+ Channels（聊天渠道）+ Skills + Agent Runtime + 文件记忆 + 本地执行**。
- **记忆 = 工作区里的纯 Markdown**（身份、人格、长期记忆文件每轮开头注入），可检查可搬家。
- **Skills 渐进加载**：模型只先看到技能清单，判断相关才读全文——基础提示不随技能数膨胀。
- **常驻 + 定时 + 主动**，不是「你问我答」。

**倾向**：它是**通用个人助理**路线（消息、浏览器、日程、系统操作），代码只是众多执行面之一，不像 Claude Code/Codex 以「改仓库」为中心。Hermes 同路线，再加「自动沉淀 skill」。所以你的判断对：**它们不倾向于代码**，倾向于「长期关系 + 记忆 + 渠道」。这条线更接近你要做的 NPC。

## 5. 你自己写 Agent：建议（⚠️ 我的综合，有出处的标 🟡）

1. **先写 ~100 行最小循环**，别上框架（🟡 论文：11 个系统无一使用）。循环 = 模型→工具调用→执行→回灌→直到不再调用工具。
2. **检索用确定性手段**（grep/glob/读文件/索引），别一上来就向量库（🟡 论文）。
3. **记忆 = 文件**：索引常驻 + 全文按需 + 空闲时整理去矛盾（你已经走在这条路上）。
4. **提示词排序为缓存服务**：稳定内容在前，动态在后；别在前缀里塞时间戳。
5. **工具报错、截断、超时都要结构化**，作为观察回给模型。
6. **权限在 harness 而不在提示词**：白名单 + 确认；这和你「白名单只管安全，其余放权」的原则一致。
7. **子代理 = 上下文隔离工具**（不是为了「多智能体」本身）。你手动开两个对话就是这个。
8. **要有验证步骤**（跑测试/自检）才算闭环：收集上下文 → 行动 → 验证（Anthropic Agent SDK 的循环表述 🟡）。
9. **脚手架可删**：每加一个机制写下「它在补模型的什么短板」，模型升级时回头审。
10. **行为策略放配置不放提示词散文**（🟡 论文趋势），便于版本管理和复现。
11. **日志是调试依据**：把每次「观测→决策→动作→结果」落盘，方便复盘和调试。（不是为了训练 NPC——那是 Life Games 的事，不在 Synapsis 范围内。）

## 6. NPC 控制模型：LLM 与这些模型的共通点 + 建议

> ⚠️ **范围（👤 2026-10-08）**：Synapsis 里的东西**不拿来训练游戏 NPC**，那是 Life Games 里做的事，不属于 Synapsis 项目。本节只是**学习思路**的笔记（给 Life Games 那边参考），**不是 Synapsis 的路线图**，Synapsis 的待办里不要出现 NPC 训练。

### 6.1 先摆清楚 ARDY / MotionBricks 到底覆盖哪一层（✅ 论文/页面）

它们**只是「动作空间」那一层**，而且是**纯运动学**（没物理、会脚滑、不感知场景）：

| | ARDY | MotionBricks |
|---|---|---|
| 条件输入 | 在线文本、根轨迹/路点、全身关键帧、稀疏关节/末端、脚接触关键帧 | **不用文本**（嫌歧义）；速度/朝向/风格、事件、稀疏关键帧、物体位姿 |
| 输出 | 一帧一帧的 3D 动作（根位置朝向 + 身体潜在 token） | 全身运动学（关节位置/旋转/速度/接触） |
| 结构 | 自回归 + DDPM；窗口 40 帧(2s@20fps)，约 156M 参数，4～10 步去噪 | 离散潜在 token（T/4）+ 掩码 token 预测，**一次前向**；约 150M；2ms/次(5090) |
| 观测 | 只看自己过去的动作 token（滑窗，演示 8s）；**不感知场景/物体** | 无场景感知；物体靠「smart object」代理关键帧 |
| 重规划 | 新输入或缓冲不足时 | 约 10Hz 或指令变化 |

**所以你说的「更全面」的方向是对的**：它们没有观测空间（感知世界）、没有决策空间（想做什么）。ARDY 里 LLM 只当文本编码器，不是规划者。

### 6.2 LLM 与这类模型的共通点（这是个很好的统一视角）

1. **都是「序列模型 + 条件」**：LLM 是 token 序列 + 提示；MotionBricks/ARDY 是**离散化的运动 token 序列**（FSQ/多码本）+ 约束。⚠️ 区别只在 token 是词还是姿态片段。
2. **都靠「历史窗口 + 重规划」**：LLM 有上下文窗口；ARDY 有运动历史滑窗；二者都在「预算不够时压缩/截断历史」。
3. **「稀疏约束 + 掩码补全」 ≈ 提示词**：MotionBricks 缺失约束用掩码嵌入——和给 LLM 一个不完整的提示、让它补全同构。
4. **都用 classifier-free guidance / 条件丢弃**训练来获得「可控」。
5. **「慢规划 + 快执行」的分频**到处出现：MotionBricks 10Hz 重规划、帧级解码；Voyager 的 LLM 规划 + Mineflayer 执行；层级 LLM+RL 论文。
6. **接口即契约**：MotionBricks 的「smart primitive」把意图转成稀疏关键帧——**正好就是 LLM 和动作模型之间的接口**。

### 6.3 观测 / 决策 / 动作 三空间怎么搭（⚠️ 我的建议，参考 Voyager / SIMA / Generative Agents 🟡）

- **动作空间用「原语 + 参数」，别用原始动作**：Voyager 选了「代码」当动作；你可以让决策层输出「去那里 / 看他 / 拿起 X」→ 转成 MotionBricks 式稀疏约束。SIMA（像素→键鼠）是研究目标，不适合你的预算。
- **观测空间先做「结构化状态序列化器」**：LLM 版（文字摘要）和小模型版（向量）都从同一份世界状态生成。🟡 研究反复指出瓶颈就在这层，不在模型。
- **决策分两层**：LLM 慢时钟（子目标边界才重决策）+ 小而快的策略（反应、躲避）。KAIROS 的「tick→决定做不做」是现成范式。
- **记忆比底座模型更决定长程连贯**（Generative Agents 消融：去掉反思，48 个模拟小时内行为退化成重复、无上下文）。⭐这和你 Life Games 的「观测/记忆/个性/情绪/决策分层 + 兜底与外显」一致，建议**反思/去矛盾**也进你的图。
- **训练路线（先用 LLM 跑通，再蒸馏）**：① LLM + 规则/行为树跑通闭环 → ② 记录「观测→决策→动作→结果」日志（§5.11）→ ③ 把高频决策蒸馏成小模型，LLM 只留给少见的慢决策。别一开始就端到端。
- **评估要把「可信度」和「胜率/完成率」分开测**（🟡 小样本研究：LLM 引导的 NPC 胜率与行为树相当，但 60% 的人觉得更像真人）。
- **已知风险**：ARDY/MotionBricks 脚滑、不懂物理/场景——要和物理跟踪层或 IK 兜底配合；MotionBricks 论坛反馈「做玩家控制会很糟，做 NPC 可以」（🟡 论坛，单一来源）。

## 7. 一手更新（✅ 官方 changelog / 文档，2026-10-08 读取）

> 覆盖范围：changelog 只读到 **2.1.285（9/29）～ 2.1.294（10/8）**；4～9 月的条目页面太长没读，所以「什么时候加的」我不知道。

- **子代理/团队**：`agent.spawn`、teammates、`effort` 参数；子代理被唤醒时**保留之前的思考和提示缓存**（2.1.290）。

- **Hooks 失败即拒绝**（2.1.288）：PreToolUse / PermissionRequest 钩子**匹配失败时阻止调用**而不是放行。→ 安全层应该「失败时关门」。
- **Auto mode**：用分类器代替逐次弹确认；对话太长分类器吃不下时自动压缩（2.1.288）。
- **压缩教训**（2.1.293）：修了「压缩后 Claude 把自己压缩前做完的事当成没做、撤回或重做」——**摘要里必须明确标「已完成」**。

- **模型**：Sonnet 5.5 / Opus 5.5 / Haiku 5.5 / Fable 在位；Opus 4.7+ 与 Fable 在部分平台默认 1M 上下文。

**Anthropic Agent SDK 官方文章（✅）要点**：循环 = **收集上下文 → 行动 → 验证 → 重复**；**文件系统即上下文**，先用 agentic search（grep/tail），**嵌入检索只在需要更快或更多样时再加**（更不准、难维护、不透明）；子代理 = 并行 + **隔离上下文，只回传相关摘录**；工具设计要省上下文，高频动作做成一等工具；能用**代码**表达的任务就用代码（精确、可组合、可复用）；验证三档：**规则检查（最优先）→ 视觉反馈（截图）→ LLM 当裁判（最后，慢且不稳）**；失败案例要回头看「是不是少了工具」，反复失败的就给工具调用加**形式化规则**。

## 8. 对照 Synapsis 内置 AI 的差距（⚠️ 读了 `core/agent.js`、`core/memory.js` 后的判断）

**你们已经做对的**（和官方一致）：索引常驻 + 全文按需；系统提示词不变前缀吃缓存；格式错误时把错误告诉模型重试一次；`applyPlan` 只执行 `ok` 的动作（= 失败即拒绝）；写动作人确认；`replace` 旧的进 `_过期的/` 不删；`place` 给原语不给剧本（= 官方「给工具，不给剧本」）。

| # | 差距 | 现状（代码） | 官方做法 | 建议 | 代价 |
|---|---|---|---|---|---|
| **A** | **只能看见「当前页的节点清单」** | 一轮定音；唯一的多一跳是 `read` 记忆（`runAgent` 只再问一轮）；看不到节点正文、别的页、搜索 | 收集上下文是循环的第一步，grep 式 agentic search | 把 `read` **泛化为只读原语**（读某节点正文 / 列某页 / 搜项目），限 3～4 跳；**写仍然 plan→确认**。`cli.js` 已有 overview/outline/get，可直接复用。符合「白名单只管安全、给原语」 | 中 |
| **B** | **执行后没有验证** | 只有执行前 `validateAction`，和一个「嘴上说做了手上没动作」的文字检查；`place` 让模型自己算坐标，**算错重叠了没人告诉它** | 验证：规则检查优先 | 执行后用**规则**检查（卡片是否重叠、目标节点是否存在），结果显示给人，并带进下一轮上下文让它自己修；**不要用 LLM 当裁判** | 小 |
| **C** | **记忆只增不整理** | 追加或整份替换；索引无上限；无类型；无矛盾检查 | 四类型；索引 200 行 / 25KB 上限，接近就提醒精简；写入时教它合并 | ①索引加上限与提醒 ②frontmatter 加 `type`（用户 / 反馈 / 项目 / 参考），feedback 类写「为什么 + 怎么用」 ③ **用户点「整理记忆」才跑**：AI 列出重复 / 冲突 / 过期 → 人确认 → 旧的进 `_过期的/`。**不做闲时自动整理**（官方没写，只是泄露传闻） | 小～中 |
| D | 历史没有压缩 | 只留最近 8 轮、存 30 条 | 自动压缩；教训：摘要要标「已完成」 | **暂不做**（8 轮够用）；以后做的话摘要必须标已完成的动作 | — |
| E | 手撕 `{…}` 解析 JSON | `parseReply` 取第一个 `{` 到最后一个 `}` | 原生工具调用 | 在线模型可改用函数调用，解析失败会少；但会牵动 8B 本地那套，**先不动** | 中 |
| F | 「提议 → 人是否执行 → 结果」没有留痕 | 有 `ai_log.jsonl`，**我没验里面有没有「人确认 / 拒绝 / 改了什么」** | 官方：用真实使用做 eval 集 | **待验**：确认是否记「提议→人是否执行→结果」；没记就补（便宜，且是§5.11 的落点） | 小 |
