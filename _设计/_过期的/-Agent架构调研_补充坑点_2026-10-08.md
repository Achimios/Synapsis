# 补充：动手做 §8 前要知道的（写这套 AI 代码的那个会话留的，2026-10-08）

> 配套 [`-Agent架构调研_2026-10-08.md`](-Agent架构调研_2026-10-08.md) §8。那份的判断和顺序（B → A → C①②）我都同意，这里只补**代码里的坑**和**一处漏掉的问题**。

## 0. 漏掉的问题（建议排在 B 前面，最小）：历史里分不清「提议了」和「执行了」
- `runAgent` 存短记忆时，`done` = **提议时**校验通过的动作描述（`core/agent.js` 里 `pushChat(... done: actions.filter(a => a.ok).map(a => a.desc))`），**不是人确认执行过的**。
- 喂给模型的历史是 `{say, actions}`（提议原样），**没有「人执行了 / 没执行 / 改了主意」**。`/ai/apply` 也不回写 `ai_chat.json`；界面里的 ✓ 只是前端本地改的。
- 后果：模型分不清上一轮到底做没做 —— 👤 遇到过的「为什么什么都没做」就有这层原因；也正是官方压缩教训「摘要要标已完成」的同一件事。§8-F（日志里记提议 → 人是否执行 → 结果）也落在这儿。
- 做法：`/ai/apply` 成功后，把最后一轮标 `executed: [desc…]`；人按 Esc / ✗ 不要 → 标 `rejected: true`（前端调一个小接口，或者下一轮请求带上）。喂历史时在 assistant 那条后面加一句「（人确认执行了：…）/（人没执行）」。

## 1. B（执行后验证）落在哪
- 坐标是**前端**应用的：`applyPlan` 返回 `moves`，`shell.jsx` 里 `move(d.moves)`。但 `applyPlan` 手里有 `fixedBoxes`（前端量的卡片 x, y, w, h）+ `moves` → **服务端就能算重叠**，跟 `moves` 一起返回 `warnings`，不用等前端。
- 重叠判断可以直接用 `core/arrange.js` 的 `overlaps(r, q, gap)`。
- 警告要**进下一轮上下文**（跟 §0 同一处：标在那一轮上），模型才能自己修；界面上在「✓ 做了什么」下面显示。

## 2. A（只读原语、多跳）怎么接
- 现成的骨架：`runAgent` 里「模型回 `{"read": [...]}` → 附全文 → 再问一轮」。泛化成 `{"look": [{"node": "n3"} | {"page": "n5"} | {"search": "词"}]}`，**最多 3 跳**，每跳把结果附在 user 消息后面再问。
- 能直接用的：节点正文 `loadWorkspace(root).graph.nodes.get(id).body`；别的页 `pageContext(ws, 那个节点 id)`（编号要另起一套，或者只读不给编号）；搜索 `grepProject(root, q)`（`core/workspace.js`）+ `core/search.js`。
- 每跳都会把整份提示词重发：系统提示词不变 → 在线缓存命中，不贵；但要在日志里一跳记一条（`kind: 'AI 指令（查看 n）'`），不然调试看不懂。
- 只给宽松版（在线）。`isLoose(cfg)` 已有。8B 不开 —— 同意文档的判断。
