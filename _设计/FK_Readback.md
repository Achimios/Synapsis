# FK 读回：图怎么从项目里知道「现在怎样」

> 2026-10-08 · Opus 起草；当晚👤拍板方向，实现交给 Sonnet（见 §4）。起因：`ASTRA的思考/-Claude的审阅.md` §2.2——`Philosophy.md` 说状态「从项目读回」，实际全是手填。
> 👤 = 用户原话。实测 / 推测分开标。

## 0. 先把问题问对

「读回」很容易被理解成：**让程序自动算出 done / partial / todo，替掉手填**。我认为这个方向是错的。

done 是一句**主张**（「我说这块做完了」），程序读回来的是**观测**（「文件在、符号在、某次测试过了」）。两者回答的问题不同：
- 观测永远说不出「做完了」——测试全过也可能目标本身定错了。
- 主张没有观测撑着，就会悄悄变成谎言。

这正是 ASTRA 拆出来的两个轴（主张类型 / 证据），也是你的「外部群」：**图是内部，项目是外部；外部的反馈不该被内部改写，而是摆在旁边对照。**

所以提案是：
> **手填的 status 留着，当主张。FK 只产出观测，摆在主张旁边；两者对不上时提示，不自动改。**

这和 `Navigation.md` §3 的观察层原则一样：只提示、不改图。

## 1. 能从项目里读回什么（按代价从低到高）

| 级 | 观测 | 从哪读 | 现状 | 代价 |
|---|---|---|---|---|
| L0 存在 | `code:` 指的文件 / 符号还在不在 | 文件系统 | ✅ 已做（`check`） | 0 |
| L1 新鲜 | 标「实测」之后代码改过没有 | 文件 hash / git | ✅ 已做（`evidence_hash`） | 很低 |
| L2 锚点 | 代码里的 `>v<` 标记和图里的节点是否一一对上 | grep `>v<` | ❌ 没接 | 低 |
| L3 测试 | 绑定的测试最近一次过没过、在哪个版本 | 测试结果缓存 | ❌ | 中 |
| L4 运行 | 回放 / 仿真里的行为指标（Life Games 的 NPC） | 被规划项目自己的输出 | ❌ | 高，属于研究 |

### L2 值得单独说：这是现成的、几乎免费的外部群
实测：
- Synapsis 自己的代码里已有 **42 个文件**用 `>v<emoji大标题-小标题-说明` 注释做功能锚点（`_开发索引.md` 有锚点表），而且这条规矩在 `bootstrap/` 里，**所有新项目都会继承**。
- 图里已有 **72 个** `code:` 绑定（Synapsis 自己 + Life Games 研究），写法是 `文件#符号`。
- Life Games 的代码**没有** `>v<` 锚点（它比 bootstrap 规矩早）。

`文件#符号` 的毛病：重构一挪就断。锚点的好处：它是写代码的 AI 顺手留的，跟着功能走，不跟着文件走。
可能的做法（**推测，没验证**）：节点可以写 `anchor: 🤖AI指令-宽松版`，check 双向对：
- 节点说有、代码里找不到 → 「锚点丢了」（重构删掉了？）
- 代码里有、图里没节点 → 「这块代码没进图」（图落后于项目——这才是最常见的腐烂）

第二条是 L0 / L1 都做不到的：**它能发现图里压根没有的东西。**

### L3 / L4 先不动
L3 需要「谁跑测试、结果存哪」的约定，跨项目不统一（Synapsis 用 `core/test`，Life Games 用 `node tests/run.js`，59 条）。L4 就是 ASTRA 说的软件雅可比，是 Life Games 的研究，不是 Synapsis 的功能。

## 2. 显示：主张 vs 观测

卡片上现在只有一个状态色。要加的只是「对不上」这一种信号，例如：
- 标 ✅ 但锚点丢了 / 实测后代码改过 → 状态色旁一个小 ⚠，悬停说为什么
- 代码里有锚点但图里没节点 → 不在卡片上（没有卡片），在 check / 概览里列出来

**不新增状态值、不自动改 status。** 用户想改就自己改（或让 AI 提议、人确认）。

## 3. 成本账本（ASTRA A2）

| | 收益 | 新增维护 |
|---|---|---|
| L1 | 实测不再永远是绿的 | 无（自动记 hash） |
| L2 | 图不会悄悄落后于代码；重构不断链 | 每个节点要不要写 `anchor:`——**可选**，不写就只有 L0 |
| L3 | 「过没过」有据可查 | 要统一测试结果格式，跨项目有成本 |

判据仍是 `Philosophy.md` §7.6：能不能让你**更快想清楚一件游戏设计的事**。L1、L2 主要防的是「以为图是对的，其实落后了」——在图越来越大时最值钱。
