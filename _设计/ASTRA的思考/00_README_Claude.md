## 先说清楚发生了什么

上一轮只在聊天里进行了探索，没有自动修改 `Philosophy.md`，也没有写入用户的本地仓库。本包是在用户提出下载需求后才实际生成的 Markdown 文件。

本包依据已上传的 **五份设计文档** 与本对话，不代表读取了整个 `_设计` 文件夹。没有访问本地项目目录，没有查看或运行源代码，没有发送给 Claude，也没有执行任何工程修改。

**作者归属：用户原话、既有文档结论、ChatGPT 新提案必须分开。所有新增仍待用户评审；用户表达喜欢，不等于逐条批准设计与实现。**

## 最重要的使用方式

先读 `Exploration_Addendum.md` 理解严谨性与发散灵感，再读 `Design_Review.md` 对齐现有决定。要看拟议落位，可看 `proposals/Philosophy.md` 的 §8 和 `proposals/Navigation.md` 的 §5。

两份 `proposals` 都完整保留了对应上传原文，只在末尾追加新章节。**不要直接覆盖仍在开发中的本地文件。** 请先对照当前分支、保留期间新改动，再由用户决定是否合入讨论章节。

`patches/discussion_additions.patch` 是相对上传快照、以设计文件所在目录为基准的纯追加差异，供审阅，不是要求自动执行的脚本。它不包含代码变更或配置变更。

## 你们已经有的原则，不要算成这次新增

渐进形式化、IK／FK 闭环、两套投影的滑杆、观察层只提示不改图、嵌入“同类不等于相连”、一节点一 Markdown、按摩擦日志推进，都在原材料中已有依据。

本轮新增主要是：换基／投影／重新建模的区分；形式化与证据的分离；意图澄清与实现求解双环；可逆的形式化；局部参数—行为敏感性研究；由 AI 提出区分解释的实验。它们仍是候选，不是已验证成果。

## 不要改动的开发边界

按原 `Spec_v1.md` 的规则，未来想法不自动进入 v1。按原 `Decision_Canvas.md`，画布底座已有 React Flow 决定；本包没有提供推翻证据。

保留现有数据格式、人工设计布局与逐节点低摩擦原则。不要为了容纳这份讨论立刻做全图 schema 迁移、重构核心或搭一个通用平台。

本包没有原始测试样本，文档中“已实现／实测”是对原材料的引用，不是本轮复现。外部论文、库许可、模型能力及竞品现状没有在本轮重新核验。
