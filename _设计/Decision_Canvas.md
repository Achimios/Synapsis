# 决定：画布用 React Flow（2026-10-07）

> 👤 用户：「考虑到未来复杂的矩阵、向量、决策树嵌入显示，和基变换视角，我们应该确定下用 react flow 还是 tldraw 了吧？」→ Claude 给证据，选 React Flow。
> tldraw 版代码留在 `_过期的/tldraw_spike/`（git 里也能找回）。推翻这个决定要给新证据。

## 证据（同一外壳、同一数据、两边各实现同一套功能，自动化测试两边都过过）
| 每加一个功能的代价 | React Flow | tldraw 5 |
|---|---|---|
| 节点内嵌交互（原地展开列表） | 节点就是 DOM，尺寸自动撑开 | 拦 pointerdown；形状高度**手算**随展开行数变 |
| 双击钻进 | 一个回调 | 已选中时 `onDoubleClick` 不触发，自己按坐标找 |
| 边 | 边就是数据（source/target） | 箭头 + 绑定，双向翻译同步、锁定受管箭头 |
| 选中框 / 命中 | 不用管 | `getIndicatorPath`、实心几何，各踩一次 |
| 坑（_LEARNINGS） | 1 个（保留 measured） | 3 个 |
| 画布代码 | ~60 行 | ~150 行 |
| 打包体积 | 416 kB | 1.7 MB |
| 许可 | MIT | 自有许可；本地也有生产水印 |

## 未来需求对照
- **矩阵热力图 / 向量 / 决策树嵌入节点**：RF 节点是普通 React 组件（canvas/SVG 随便放），内部控件加 `nodrag` / `nowheel` 类即可交互；决策树 = 子流程（parent node）或钻进去的子图。
- **基变换视角**（中键旋转，见 `Navigation.md` §2）：节点坐标只是数据，两套投影之间插值逐帧更新即可。
- **tldraw 唯一明显优势 = 自由手绘**：需要时在 RF 上叠一层手绘（如 perfect-freehand，MIT），不换底座。

## 没验证的
- 用户还没亲手比较两边手感（本决定基于实现成本与未来需求，不是手感）。
- 上千节点的性能两边都没测。
