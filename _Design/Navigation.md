# 导航：在自己脑海里导航（需要下功夫的一块）

> 2026-10-07。👤 = 用户原话。实现状态：✅ 已做（spikes） / 💡 想法，未做。

## 0. 定位（👤）
> 「Google 的诞生是允许你在世界 web 中导航，而 Synapsis 是帮助你在自我脑海中导航和记录。」

所以导航不是附属功能，是**主功能**之一。层级会非常多（游戏设计规划 ⊃ AI 行为 ⊃ 决策 ⊃ 状态机 …）。

## 1. 导航原语（按浏览器 / 地图 / IDE 的已有经验）
| 原语 | 类比 | 状态 |
|---|---|---|
| 钻进 / 退出（面包屑） | 文件夹 | ✅ 双击 / Alt+↑ / 面包屑 |
| 后退 / 前进 | 浏览器 | ✅ Alt+← / Alt+→ |
| **每个范围记住视图**（平移+缩放），回来时还原 | 地图 App | ✅（👤「返回上一级后得记住视图大小和位置」） |
| 传送门：跨层连线的端点，双击跳过去 | 超链接 | ✅ |
| 跳转：Ctrl+K 模糊搜索任意节点（名称 + 语义） | VS Code Ctrl+P / Google | 💡 |
| 语义缩放：缩小只看标题，放大才显示内部；缩到底自动「退一层」、放大到节点上自动「钻进」 | 地图的 LOD | 💡 |
| 沿边走：选中后方向键沿入/出边跳 | 图游走 | 💡 |
| 迷你地图标出「我在哪一层、哪一块」 | 游戏小地图 | 💡（RF 有平面小地图，没有层级感） |

## 2. 中键 = 旋转 = 基变换（👤 2026-10-07 灵感，**等更多灵感再定**）
现在中键和右键都是平移，浪费了一个轴。想法：**中键拖动 = 换视角**。

同一批节点其实同时有多套坐标：
| 投影（基） | 坐标从哪来 |
|---|---|
| 设计视图 | 人摆的 x,y（默认） |
| 层级视图 | 树布局 |
| 流向视图 | 按边分层（现在的自动布局） |
| **语义视图** | 节点文字的嵌入向量 → PCA/UMAP 到 2D（见 §3） |
| 标签视图 | 两个标签轴张成的平面（如 x=频率层，y=实现状态） |
| 时间视图 | 创建/修改时间、或开发进度 |

「旋转」= 在两套投影之间**连续插值**（节点平滑地从一套坐标滑到另一套）。这正是高维空间里的基变换 / 不同切片视角：
每个节点是高维向量（设计坐标 ⊕ 嵌入 ⊕ 标签 ⊕ 时间），屏幕是它的一个 2D 切片，中键拖 = 转动切片平面。
- 好处：保留**物体恒常性**（看着节点滑过去，就知道「它在另一种眼光下跑到哪」），这是切换视图时最容易丢的东西。
- 风险：插值中间态可能没有意义；先只做「两套投影之间的滑杆」验证值不值。

## 3. 向量空间 / 语素 / 标签：引导思维与结构感知（👤 问「是否有一个地方可以嵌入」）
放的地方：**节点的元数据 + 一个「观察层」**，不改节点本身。

1. **标签 = 正交于层级的轴**。层级只能表达「属于」；标签表达「横切」（如 #兜底 #外显 #实时 #待验证）。用途：过滤、着色、标签视图（§2）。成本低，v1 后最先做。
2. **嵌入向量（本地模型）**：每个节点的文字 → 向量（LM Studio 的 embeddings 接口可试，**未验证**）。三种用法：
   - **语义近邻**：「这两个节点意思很近，但没有连线」→ 提示可能漏了关系（结构感知）
   - **语义视图**：投影到 2D 看思维的「地形」，哪里扎堆、哪里空白（空白 = 还没想到的区域？）
   - **语义搜索**：Ctrl+K 不只按名字，按意思找
3. **结构度量（借 Google 的 PageRank 思路）**：按连线算中心度 → 「你以为的核心」vs「连线显示的核心」；孤岛、桥节点、只进不出的节点。这是用链接结构反过来照见思维。
4. 原则：这些都是**观察层，只提示不改图**；提示要标「推测」，由人决定接不接受（同虚影节点）。
