# Synapsis · 哲学与定位

> 2026-10-07 与用户讨论整理。👤 = 用户原话或用户拍板。

## 1. 一句话
**Obsidian 的图是笔记链接的副产物，回答「我知道什么」；Synapsis 的图是设计出来的结构，回答「我在造什么、造到哪了」。**

| | Obsidian 图谱 | Synapsis |
|---|---|---|
| 单位 | 一篇篇文本，全局 | 一个项目内部的结构：脑区 → 区块内部 → 神经元/空间 |
| 位置 | 力导向，无意义 | 人摆的，有意义 |
| 边 | 链接，无类型无方向 | 有类型、有方向、带证据等级（估计/实测） |
| 状态 | 无 | ✅◐○，**从项目读回**（不是手填） |
| 层级 | 平 | 一等公民，可钻进去 |
| 绑定 | 一堆笔记 | 一个工作空间（被规划的项目） |

## 2. 软件运动学（👤用户的框架，见 `E:\z_from_oldLaptop\ObsidianVaults_V3\-人类思维笔记\L_AkiDynamic\3-1*`）
- 动力学 = 代码本身（LLM 时代已不是瓶颈）
- **运动学 / 显现层 = Synapsis 画出的结构**
- 意图路由 = 草稿节点写意图 → 导出给 LLM → LLM 建执行链
- 闭环：**IK 顶→底**（人画意图 → LLM 改代码）；**FK 底→顶**（读回 `_DevProgress` / `_DevIndex` / check 结果 → 节点变色）

👤「瓶颈不再是代码本身和技术困难，而是对架构的掌控、对项目结构的了解、对代码关系的可见。尽量降低专用技巧的入门成本，中间由 LLM 桥接，人类意图的传达和对关系的可见最重要。」

## 3. 三件真正新的东西
1. **每条主张带证据等级**（【实测】【设计】【估计】【未验】成为数据结构）
2. **草稿能被 lint**：节点标 ✅ 但 code 指向不存在 → 报错，草稿不会悄悄变成谎言
3. **LLM 是一等读者/作者**：渐进披露导出 + CLI 查询 + 补丁式修改

## 4. 形式化是逐节点的，不是全工具的
`便签 → 有类型 → 有 spec → 有 code 链接 → 有实测`。check 只对升到该级的节点生效。
（参考：Shipman & Marshall 1999 *Formality Considered Harmful* —— 过早要求结构，人会停止思考或乱填。）

## 5. 思维路径的证据（不是猜）
`Life Games/研究/用户笔记_AI空间.md` 的写法：**先甩一串清单（`/` 分隔）→ 再补关系 → 再加横切原则**。没有一步是「拖一个方框」。
→ 第一版：**打字优先，摆放其次**（大纲式输入，节点出现在画布，之后再拖）。

## 6. 范围（👤）
- 先只做游戏 AI 行为规划这一个案例；通用性只留在数据模型里。「建罗马和巴黎，不建迈阿密」——路（数据模型）先铺好，功能跟着案例长，长堵了就安排一次奥斯曼式重构。
- 主要给**人类自己思考草稿**用；方便编辑；可输出结构化文本指挥 LLM。
- 将来用于游戏设计规划，层级会非常多；AI 行为只是视图里一小块。

## 7. 首轮讨论定下的东西（2026-10-07，防止压缩后丢失）
> 原始对话在 Claude Code 的会话记录里；这里是结论。👤 = 用户定的。

**7.1 「超越 Notion」到底超越在哪**（Claude 首轮的判断，用户认可）
画布、拖拽、折叠只是壳（库都做得很好）。真正新的是 §3 那三件：**证据等级成为数据结构**、**草稿能被 lint**、**LLM 是一等读者/作者**。三者合起来才是「下一代思维草稿 / PLAN / PRD 工具」。

**7.2 思考与规格是相反的**
思考要低摩擦、允许模糊；规格要类型、校验、证据。解法 = §4「形式化是逐节点的」：凌晨三点随手记的便签和接上 `code` 的决策节点可以在同一张图里。Notion 要你先建数据库再填内容；Synapsis 是先有内容、结构慢慢长出来。

**7.3 存储：一节点一 .md（而不是一图一 JSON）**——理由：人能直接读写、LLM 原生（文件本身就是节点卡）、按节点 git diff 冲突少、一个节点可出现在多张图、直接兼容 Obsidian；坐标单独放 `_layout.json`。已实现（`core/workspace.js`）。

**7.4 👤 用户回答的四个问题**
1. 主要读者：**人类自己思考草稿**；要方便编辑；可输出结构化文本给 LLM、指挥它。
2. 范围：**先不通用**——只做游戏 AI 行为这一个案例；以后用于游戏设计规划，层级会非常多，AI 行为只是视图里一小块。
3. 「建罗马和巴黎，不建迈阿密」：一个案例上的成熟进步带来整体的结构探索（发散式推进）。七丘 = 游戏NPC状态空间组（罗马的发源地）。
4. 和玩法比的优先级：用户没给数字；Synapsis 由用户和 Claude 一起维护，用户累时文字丢在对话里，Claude 代记。

**7.5 检验方式**
- **自举**：用 Synapsis 写 Synapsis 自己（`__synapsis/Synapsis/`，`check` 0 错）——写得顺说明通用，卡住的地方就是下一步。
- **需求来源 = 摩擦日志**（`-给人类的解释/-摩擦日志.md`），不是功能清单。

**7.6 风险提醒（基石原话的延伸）**
这是「造工具的工具」，最容易陷进去。「别把地基当成目的」——判断标准：今天的改动有没有让用户**更快地想清楚一件游戏设计的事**。

**7.7 后来定下的（详见各文件）**
- 画布 = React Flow（`Decision_Canvas.md`）；导航是主功能、中键 = 基变换、嵌入衡量「同类」不是「相连」（`Navigation.md` §2–§3.6）
- 托盘程序 = Electron（Node + Chromium，Obsidian 同款），不需要 Python
